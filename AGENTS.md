# Repository Guidelines

## Project Structure & Module Organization
- `src/index.ts` is the Worker entrypoint and exports the routed app.
- `src/app.ts` defines the shared Hono factory/router helpers and app-level middleware:
  - secure headers + CSP nonce support
  - global rate limiter (`RATE_LIMITER` binding)
  - request logging
  - CORS based on `CORS_ORIGINS`
  - `notFound` and `onError` handlers
- `src/routes/index.ts` registers route modules onto the main app (`/`, `/contact`, `/health`).
- Feature routes live in `src/routes/<feature>/<feature>.index.ts` with handlers in matching `*.handler.tsx` files where applicable.
- UI is server-rendered with Hono JSX:
  - `src/components/layouts/basic.tsx` is the HTML document/layout shell.
  - `src/components/home/*` and `src/components/contact/*` contain page-level UI pieces.
- Styling source is `src/styles/tailwind.css`; compiled output is `public/styles.css`.
- `wrangler.jsonc` defines Worker config, assets directory, env vars, rate limits, and production routes.
- `worker-configuration.d.ts` is generated by Wrangler (`npm run cf-typegen`); do not edit it manually.

## Build, Test, and Development Commands
- `npm install`: install dependencies.
- `npm run dev`: local development workflow:
  - build Tailwind once (`tailwind:build`)
  - run Tailwind watcher (`tailwind:watch`)
  - run `wrangler dev` concurrently on port `3000`
- `npm run dev:worker`: run Wrangler only (no Tailwind watcher/build).
- `npm run tailwind:build`: compile/minify Tailwind CSS to `public/styles.css`.
- `npm run tailwind:watch`: watch/rebuild Tailwind CSS during development.
- `npm run deploy`: build Tailwind then deploy Worker with minification.
- `npm run cf-typegen`: regenerate Cloudflare binding types after Wrangler config changes.
- `npm run lint`: run ESLint checks.
- `npm run lint:fix`: auto-fix lint issues.

There is currently no `npm test` script. If tests are added, include a documented test command in `package.json` and README.

## Coding Style & Naming Conventions
- Use TypeScript with ES modules, strict typing, and the `@/*` path alias.
- Route module naming:
  - files: `<feature>.index.ts` and optional `<feature>.handler.tsx`
  - router constants: `camelCase` (example: `healthRoute`)
  - handlers: `verbFeature` (example: `getRoot`, `getContact`)
- Prefer alias imports (`@/...`) over deep relative paths.
- Keep imports grouped and alphabetized (`builtin`, `external`, `internal aliases`, then relatives).
- Follow ESLint style conventions enforced by config:
  - single quotes
  - semicolons
  - trailing commas for multiline literals
  - spaced object braces

## Commit & Pull Request Guidelines
- Use Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`).
- Keep commits focused and lint-clean.
- PRs should include:
  - what changed and why
  - API/configuration impact notes (especially `wrangler.jsonc`)
  - validation evidence (`npm run lint`, and tests if/when present)
  - sample request/response payloads for behavior changes

## Security & Configuration Tips
- Keep `CORS_ORIGINS` strict and environment-specific.
- Verify `RATE_LIMITER` binding names and namespace IDs before deploy.
- Keep CSP updates in sync with external dependencies (fonts/scripts) used by layout/components.
- Do not commit secrets; use Wrangler-managed environment configuration/secrets.
